## Honest transfers: what an agent's own transaction gets

From the fetched blocks, the executed simple transfers were taken — one System `Transfer` or SPL Token `TransferChecked` (or `Transfer`, when the block names its mint), beside nothing but Compute Budget, an idempotent associated-token-account create paid by the sender, or a memo; sent by the transaction's own fee payer — up to 40, one per sender, recipient and asset; and for each a NEW unsigned legacy transaction was built: the same sender to the same recipient, 1 lamport or 1 base unit (never more than the original), the original's Compute Budget and ATA-create instructions (a memo is dropped: its text was the original sender's), a blockhash just fetched, and a zeroed signature slot. Each was first simulated by the RPC (signature verification off): one the chain would reject now — the sender's account gone or emptied, or 1 lamport into an account that does not exist, under the rent minimum (that one is rebuilt once with the original's amount) — is counted under *not built*, never verified, because refusing it would be right and would measure the sender, not the Core. Each that would land was verified with the intent `transfer` and its amount, recipient and asset stated, under the built-in Gaming profile. Nothing was signed or sent: the bytes went to the RPC's simulateTransaction and the local Core's /verify only.

What this measures: the decision an honest agent's own simple transfer gets from this Core against today's mainnet state. What it does not measure: swaps (their own section below) or any other protocol, what happens after signing, or wallets the runner controls — the senders are real wallets as they stand now.

## Reading this

- The replay's transactions are other people's, replayed unsigned against today's state with the intent an honest agent would declare. A program with no evidence is refused by policy, and a transaction whose inputs moved since fails simulation; that is the design, not a defect. The honest-transfer pass is the one that measures approvals.
- A refusal is never counted here as a correct or an incorrect one: this run has no ground truth about intent. `BlockedButExecuted` (L8) and the *Watched rows* are where a candidate false refusal is shown.
- `BlockedButExecuted` in L8 is the alarm firing as designed: Graphite refused a transaction somebody else executed.
- `inclusion_assurance` is `single_provider` unless a witness RPC was configured.
- The Core simulates with `replaceRecentBlockhash: true` (graphite-core/src/rpc_client.rs, `simulate_config`), so a stale blockhash cannot by itself make L3 fail; the fresh pass measures that rather than assuming it.
