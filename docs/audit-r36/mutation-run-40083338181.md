# Mutation run 40083338181 (F-015), recorded

[Assurance run 40083338181](https://github.com/Stan-lee13/graphite/actions/runs/40083338181)
mutated `80b3906` (the head merged as PR #53) in 44 shards. Each shard ran
`cargo mutants --in-place --no-shuffle --timeout 300 --file <module> --shard K/N`
against that module's selected suites. The selected suites are the `--lib` unit tests plus the
integration suites named in `.github/workflows/assurance.yml`, not the whole test suite. A
mutant these suites miss may still be caught by another suite; §4 measures that for a sample.

This page is the run's record. [CURRENT.md](../CURRENT.md) carries its summary.

## 1. What the run can and cannot say

- **No module has a complete score.** Every module has at least one shard that was killed by the
  Mutate step's 330-minute timeout or was still running when this was recorded (16:45Z; updated
  at 18:30Z for simulation integrity 3/5 and 4/5, which ended after that). Each mutant costs one
  rebuild, about 6 to 9 minutes, so about 35 mutants fit the step. The shards hold about 41.
- **The floor script passed killed shards (fixed in this change).** `mutation_floor.py` took a
  shard's count from `outcomes.json`'s `total_mutants`. cargo-mutants 27.1.0 raises that field as
  each outcome lands, so on a killed shard it equals the outcomes recorded. Of the 18 killed
  shards, 16 printed a passing "mutation score … over all N mutants". The script now counts the
  shard's mutants from `mutants.json`, which is written before the first mutant runs, and also
  requires `end_time`. The CI scripts' own tests pin this, and they failed on the old script.
  Reproduced on a probe crate: a shard interrupted after 6 of its 10 mutants passed under the old
  script and is INCOMPLETE under the new one.
- The per-shard counts below are from each job's log. They are the cargo-mutants summary for a
  finished shard, and the outcomes recorded before the kill for a killed one. "Complete" means
  every mutant the log says it found has an outcome.
